# C++ & STL: Zero to Hero

A free interactive course from your first C++ variable to interview-ready STL. 52 lessons, 19 visualizers,
a landing page, and a learner app (dashboard, notes, achievements, settings) with optional cloud sync.
Plain HTML, CSS and JavaScript. No build step.

## Run it

```bash
python tools/serve.py 5173      # then open http://localhost:5173
```
Double-clicking `index.html` also works (without the offline cache, which needs http or https).

**Offline:** after one visit online, a service worker (`sw.js`) keeps the whole app shell, every lesson, the visualizers, vendor
scripts and fonts in the browser, so the course works with no connection. Four things still need a network: the **Run** button
on code samples (it sends the program to an online compiler), sign-in and sync, the AI tutor, and the first visit. The worker is
skipped on `localhost` so edits show up on reload; add `?sw` to the URL to test it there.

## Two entry points

| URL | What | File |
|---|---|---|
| `/` | Landing page: hero, scroll story, live demo, curriculum, FAQ | `index.html`, `js/landing.js`, `css/landing.css` |
| `/app/` | The learner app (hash routes below) | `app/index.html`, `js/app.js` |

App routes: `#/welcome` (first visit), `#/` dashboard, `#/lesson/:id`, `#/notes`, `#/achievements`, `#/settings`.

## Layout

```
js/profile-core.js   pure XP, level, streak, badge and merge logic (unit-tested)
js/profile.js        wires that logic to storage and the lesson flow (completions, quizzes, time, notes, bookmarks)
js/store.js          persisted store + snapshot/restore/export/import
js/sync.js           Firebase Auth + Firestore sync (lazy-loaded; off unless configured)
js/pages/            dashboard, welcome, settings, achievements, notes
js/viz/              visualizers
content/             manifest (course outline), glossary, lessons (cpp/, stl/)
vendor/              gsap, ScrollTrigger, lenis, Firebase compat SDK
sw.js                offline service worker; its file list and version are generated by tools/build-sw.js
js/assistant.js      the AI tutor panel (signed-in learners); js/ai-md.js renders its answers safely
api/chat.js          the one serverless function: checks sign-in and a verified email, enforces daily limits, calls the AI (see AI_SETUP.md)
api/_lib/            the shared request handler, validation, prompt, quota and provider code (also used by Netlify)
netlify/functions/   Netlify wrapper around the same handler; netlify.toml holds Netlify's headers and redirect
firebase-config.js   paste your Firebase web config here to enable accounts (see FIREBASE_SETUP.md)
firestore.rules      owner-only access rules
vercel.json          cache and security headers (CSP, frame blocking), function settings
.github/workflows/   CI: runs the checks below on every push and pull request
```

## AI tutor (optional)

Signed-in learners can ask questions about the open lesson. It needs a free Groq key and a Firebase service account
set as Vercel environment variables, see `AI_SETUP.md`. The key never reaches the browser.

## Deploy (Vercel or Netlify)

It is a static site plus one serverless function: import the repo, framework preset "Other", no build command, output directory `.`.
- **Vercel:** the function is `api/chat.js`; Vercel installs its dependency (`package.json`) by itself. Headers come from `vercel.json`.
- **Netlify:** `netlify.toml` publishes `.`, sends the same headers, and routes `/api/chat` to `netlify/functions/chat.js`. Netlify sends the answer when it is complete rather than word by word, and its default function time limit is short, so raise it if the tutor times out.

Both hosts need the same environment variables for the tutor (see `AI_SETUP.md`). For accounts, follow `FIREBASE_SETUP.md` and add your domain to Firebase's authorised domains.

## Checks (run from `tools/`)

```bash
node check-content.js     # lesson structure, quiz answers
node qa-code.js g++       # compiles every runnable code sample
node test-profile.js      # XP, levels, streaks, badges, merge
node test-sync.js         # sync logic against a fake Firestore and two devices
node test-ai.js           # AI tutor backend: validation, prompt safety, limits, fallback, safe rendering, CORS, verified email
node test-sw.js           # service worker: the precache list matches the real files, install/update/offline behavior
node test-config.js       # Vercel and Netlify headers match, no inline scripts under the CSP, Netlify function wrapper
node build-sw.js          # regenerates sw.js's file list and version; run it after changing any site file
```
`check-content.js` also fails if a lesson has no visualizer or no beginner / plain / technical explanation, because the landing page promises both.
The same scripts (except `qa-code.js`, which needs a compiler) run in GitHub Actions.

## Adding a lesson

1. Add it to `content/manifest.js`. 2. Create `content/<cpp|stl>/<id>.js` with `registerLesson(...)`.
3. `python tools/sync-ready.py`. 4. `node tools/build-sw.js` so the offline cache includes it. 5. Run the checks.
